这份目录是什么

DeepSeek Harness 的 Web 界面由 packages/client/ 下的 61 个客户端插件包组成，每个包通过插槽（Slot）把组件注册进界面。本目录扫描这些包的全部 .tsx 源码，抽取每个 React 组件的名称、导出变量名、代码位置、所属包、CSS Module 类名与它消费的 --dsw-* 设计变量，并为常用组件提供实时重绘的外观示例。

外观示例的生成方式。每个示例把组件自己的 *.module.css 原文放进一个声明式 Shadow DOM（<template shadowrootmode>），并直接使用真实的 --dsw-* 变量。因此示例不是仿制图：点右上角的主题按钮即可让所有示例跟随浅色 / 深色变量一起变化，选择记在 localStorage 里，翻到别的页面也保持。条目列出多张样式表时，构建脚本按文件把类名改写成 c<下标>-<原名>，还原 CSS Module 在真实构建里的哈希隔离，避免 .root 这类同名类互相串味——细节见目录自带的 README.md。需要 JavaScript 才能产生的状态（悬停、菜单展开、弹窗、portal 定位）以静态快照配合状态附加样式呈现，并在示例标题旁标注。
覆盖范围。清单页收录全部 601 个组件的元数据（名称、变量名、来源、设计变量、CSS 类名）。重绘页覆盖共 117 个具代表性的组件：基础组件库的全部导出，加上产品层最常出现在用户视野里的组件。其余组件可在清单页按包与关键词定位到源码。

界面约定

这些规则来自 docs/web-styling.md 与 packages/client/AGENTS.md，是查阅这套组件时最容易判断错的地方。

只用变量，不写字面值

--dsw-alias-*

功能组件的 CSS 只消费语义别名，浅色 / 深色覆盖属于 ui-theme；不引入第二套主题，也不使用组件库或 Tailwind。自定义属性会穿过 Shadow DOM 边界，这正是本目录的示例能跟随主题切换的原因。

0.5px 发丝线

--dsw-elevation-panel

中性描边统一画成 0.5px（Chromium 渲染为一个设备像素）；浮层用 border: 0 加 --dsw-elevation-*，发丝描边是投影的第一层。把 --dsw-alias-border-* 与阴影层级叠在一起会被主题规格拒绝。

菜单只有一种材质

MenuSurface

下拉、右键、子菜单与选择列表都走 Menu 或 MenuSurface：半透明填充 --dsw-menu-surface-fill 与背景模糊由主题持有，功能包不得覆盖。唯一记录的例外是日程面板自有的 TaskMenu 与 ClockPicker。

复用优先于新增

ui-primitives

功能包之间不能互相导入组件，因此 ui-primitives 是唯一可以跨包复用的地方；已存在的控件不允许复制第二份，确有视觉差异时应提升为该组件的一个 prop。

复现方式

目录由仓库源码生成，不手工维护数字。

cd <目录>                          # deepseek-harness 检出里的 UIUX/，或本仓库
node tools/extract.mjs              # 扫描 .tsx，产出 data/components.json
node tools/extract-tokens.mjs       # 解析 ui-theme 样式表，产出 data/tokens.json
node tools/build.mjs                # 组装 index / primitives / product / tokens / inventory

数据源：packages/client/**/src/**/*.tsx、packages/experimental/**、packages/extensions/** 与 packages/client/ui-theme/src/styles/*.css。源码快照日期 2026-10-17。源码链接指向 deepseek-ai/deepseek-harness @ master，即生成这份目录时的上游版本。语言：中文说明 + 英文标识符（与源码一致）。
